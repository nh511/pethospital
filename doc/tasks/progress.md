## 技术组件基线

采用单仓库、Spring Boot 单体业务分包。Python只提供本地Embedding推理和tokenizer，不承担权限、预约或知识审核。两个客户端、三业务界面、统一后端；不增加业务微服务或新的付费云平台。

## 模型相关的设计修订

中文BGE small是512维，英文small的384维配置不能复用。分块从旧设计的“400～800中文字”改成按**同一tokenizer的正文320 token、重叠48 token**起步，硬约束为含特殊token的总长≤512；每块正文最多510 token，不能静默截断。查询前缀也占预算；长用户输入先在Java构建有记录的短检索query，不改变用户原始消息或急症评估输入。profile包含模型revision、维度、前缀、归一化、splitter和距离度量，切profile必须重建对应索引。

初始检索：候选20，按物种/COMMON与profile过滤，MySQL再次验证当前发布版本，补足Top5；相似度门槛通过M11-09评估集校准，不把分数作为医学可信度。知识来源和审批记录保留；AI不写正式病历。

## 每次Vibe Coding的执行方式

从一个未勾选且依赖满足的任务开始；一轮只实现这一个任务。任务的后端API责任表是范围清单，完整请求、响应、权限与错误约束继续以详细设计为准。

```text
请读取 doc/tasks/progress.md 和 doc/tasks/<module-name>.md。
本次只实现任务 <Mxx-yy>，先核对它的前置任务和现有工作树。
遵守技术组件基线、需求和详细设计，复用已有公共Service与Adapter。
完成任务列出的产物及针对风险的验证，不顺带实现后续任务或扩大业务范围。
测试与真实服务联调分开；缺Key/AppID/模型缓存时写明阻塞，不伪造通过。
将真实改动路径、执行命令、结果和必要截图写入 doc/evidence/<Mxx-yy>.md。
只有本任务验收全部通过才勾选任务；同步本页与模块的完成数。
若发现设计冲突，记录具体差异和影响后做最小一致修订，再继续验证。
```

所有任务里的构建/测试命令都是**待实现的验收入口**，不是本轮已运行结果。M01建立脚本和测试profile，后续任务创建对应测试类/文件；不能只创建空测试让命令变绿。

| 类型 | 约定命令（仓库根目录） | 证明内容 |
|---|---|---|
| 后端单元 | `.\server\mvnw.cmd -f server/pom.xml test` | 纯领域规则/校验，无供应商费用 |
| 后端数据库集成 | `.\server\mvnw.cmd -f server/pom.xml -Pit "-Dit.test=M0702IT" verify` | 真MySQL事务/索引/权限；Docker必需 |
| Web | `pnpm --dir web typecheck`、`pnpm --dir web build`、`pnpm --dir web exec vitest run tests/M1401.spec.ts` | 构建及组件行为；真实联调另验 |
| 小程序 | `pnpm --dir miniapp typecheck`、`pnpm --dir miniapp exec vitest run tests/M1501.spec.ts` | TS及wx替身行为，不能替代开发者工具/真机 |
| Embedding | `.\embedding\.venv\Scripts\python.exe -m pytest embedding/tests/test_m1103.py -q` | 真模型维度/归一化与输入边界 |
| Web端到端 | `pnpm --dir web exec playwright test` | 指向真实后端和测试数据，不全量拦截成mock |
| 依赖配置 | `docker compose -f infra/compose.yaml config` | Compose配置合法，不等于服务健康或业务通过 |

每个后端任务IT名称如M0702IT由任务ID去连字符得到；M01中的工具链类任务按手动命令验收。构建产物、测试报告和证据文件路径均为规划，不提前生成空证据或填“全部通过”。
