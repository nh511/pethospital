## 实际执行

本机Docker路径`(Get-Command docker).Source`，以下简称docker；每条成功命令最终退出码0，除列出的预期保护和首次启动探测。

```powershell
.\tools\init-env.ps1
docker compose --env-file .env.example -f infra/compose.yaml pull
docker compose --env-file .env -f infra/compose.yaml config --quiet
docker compose --env-file .env -f infra/compose.yaml up -d --pull never --wait --wait-timeout 120
python tools/check-infra.py --seed --docker '<本机Docker路径>'
docker compose --env-file .env -f infra/compose.yaml restart
docker compose --env-file .env -f infra/compose.yaml up -d --pull never --wait --wait-timeout 90
python tools/check-infra.py --docker '<本机Docker路径>'
docker image inspect mysql:8.4.13 qdrant/qdrant:v1.20.0 chrislusf/seaweedfs:4.51 --format '{{index .RepoTags 0}} {{join .RepoDigests " "}}'
```

重启前后检查均输出：

```text
PASS MySQL authenticated SQL and persisted value
PASS Qdrant authenticated point read, persistence, anonymous access denied
PASS S3 signed PUT/GET or persisted GET, anonymous object read denied
All infrastructure checks passed. Probe data is retained for restart verification.
```

MySQL通过实际SQL创建独立`infra_probe.persistence`表并读回字符串；Qdrant使用独立512维Cosine测试集合`infra_probe`及payload；S3私有桶`pet-private`内使用`infra-probe/persistence.txt`对象。重启后的脚本不再写入这三个标记，仍读回相同内容。Qdrant无key访问和S3匿名对象读取均得到401/403。

Compose只为MySQL配置内置healthcheck；Qdrant/S3的实际健康与鉴权由上述HTTP读写脚本验证，不将Compose的Running代替验证。向量为固定探针，仅验证存储，不能当作模型生成或RAG通过。
