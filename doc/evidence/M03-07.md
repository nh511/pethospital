## 已实现改动

- `V7__seed_admin_permissions.sql`：以前向迁移种入 `admin:users:view/manage`、`admin:rbac:view/manage` 四个核心 BUTTON 权限，并绑定内置 ADMIN 角色；不修改已应用迁移。
- `BackendPermissionCatalog.java`、`AdminPermissionEvaluator.java`：建立后端可执行 permission 目录；管理端请求除 WEB audience、ADMIN 角色外，还逐请求查询 ACTIVE 用户、角色、菜单和关联，数据库权限缺失时返回 403。
- `RbacController.java`、`RbacService.java`、`RbacDtos.java`、`NonZero.java`：实现 10 个 RBAC 端点，包括角色和菜单查询/创建/修改、用户角色集合、角色菜单集合；请求严格校验 version，关联集合允许内置负 ID 但拒绝 0。
- 角色与菜单保护：USER、DOCTOR、ADMIN 内置 code 不能覆盖或停用；ADMIN 不能移除四个核心动作权限；后端 permission 必须来自能力目录；菜单父链锁定并拒绝自环和祖先环。
- 事务与会话保护：用户角色变更先锁内置 ADMIN 角色行并检查最后一个有效管理员；角色权限或菜单有效性变更在同一事务递增受影响用户 `token_version`、撤销未撤销会话并写安全审计。
- `SecurityConfig.java`：账号查询/写入分别要求 `admin:users:view/manage`，RBAC 查询/写入分别要求 `admin:rbac:view/manage`，保留 WEB+ADMIN 双重边界。
- `tools/openapi-contract.mjs`、`doc/openapi.yaml`、`doc/api-coverage.md`和两端生成类型：10 个操作改为 IMPLEMENTED，新增严格 RBAC schema；当前 21 项 IMPLEMENTED、137 项 PLANNED。
- `M0206ContractTest.java`：运行时 Springdoc 精确子集扩至 21 个操作；`M0307IT.java`建立五组真实 HTTP/MySQL 断言，不使用 H2、空测试、全 mock 或跳过。
