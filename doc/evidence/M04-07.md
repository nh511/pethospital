# M04-07 审计和模型运维查询验收

日期：2026-10-31。结论：通过。审计日志与模型调用日志的只读分页查询已在真实 MySQL 8.4.13 上验证；普通管理员没有默认读取权，模型元数据与输入快照使用两级独立权限。

## 实现范围

- `OperationsLogController`、`OperationsLogService`、`OperationsLogDtos`：实现 `GET /api/v1/admin/audit-logs` 和 `GET /api/v1/admin/ai/call-logs`，支持封闭过滤、稳定分页、默认7天和最长31天的半开时间窗口。
- 审计日志要求`audit:read`；模型调用元数据要求新增的`ai:call-logs:read`；`includeContext=true`还要求`ai-consult:audit`。三项均通过当前数据库ACTIVE角色/菜单逐请求校验，ADMIN角色本身不默认放行。
- 审计响应不返回before/after快照、reason、operationKey或requestHash；模型元数据不返回providerRequestId，默认不读取inputSnapshot。只有额外上下文权限才能读取去标识快照。
- 每次成功读取追加一条固定动作审计，仅读取安全的过滤范围和返回数量；审计查询先形成结果再追加读取记录，不自包含或递归调用。两个Controller仅有GET映射，无修改或删除路由。
- `ApiExceptionHandler`补充方法不支持的统一405 Envelope，确保不存在的日志修改/删除方法不误报500。
- OpenAPI生成器、冻结契约、两端类型及`M0206ContractTest`同步两个IMPLEMENTED操作和严格schema；`M0407IT`以5组真实场景验证权限、泄漏、时间上限、读取审计和只读边界。
