# M04-04 业务附件绑定策略验收

日期：2026-10-31。结论：通过。真实集成验证使用隔离 MySQL 8.4.13，并在安全上传回归中连接项目 SeaweedFS 4.51；未新增任意附件绑定公共端点。

## 实现范围

- `server/src/main/java/com/pethospital/shared/FileBindingService.java`：提供仅供业务 Service 调用的可变附件整组替换和版本附件追加能力；业务目标、owner、createdBy 均在服务端派生，不接受客户端传入所有者。
- 服务按 `MINI/WEB`、`USER/DOCTOR/ADMIN`、业务对象归属和医生/编辑者关系校验目标；锁定 `file_object` 后要求 `READY`、用途匹配且由当前操作者上传，并复用 `CrossTableRelationGuard` 做最终跨表关系断言。
- `MEDICAL_VERSION`、`KNOWLEDGE_VERSION` 只允许追加且重复追加不产生重复行；其他可变类型以同一事务整组替换，可通过空列表解绑。
- `server/src/main/java/com/pethospital/identity/ProfileService.java`：头像更新改为调用 `FileBindingService`，仍保留公开 API 原有 `INVALID_AVATAR` 预校验；资料修改与绑定同事务提交或回滚。
- `server/src/test/java/com/pethospital/M0404IT.java`：5 组真实 MySQL 场景覆盖跨用户拒绝、可变替换、两个版本类型只追加、用途/角色校验、外层事务回滚及无任意 binding 路由。

本任务没有创建 `FileBindingController` 或 `/file-bindings` 路由。后续宠物、健康日志、病历、知识与指南业务只能在各自业务事务内调用绑定服务。
