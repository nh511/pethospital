# M04-02 私有 S3 存储适配器验收

日期：2026-10-31。结论：通过。真实服务为项目 Compose 中的 SeaweedFS 4.51 S3，未使用 mock、内存替代或公开桶。

## 实现范围

- `server/pom.xml`：固定 AWS SDK for Java v2 2.57.4，引入 S3 与 URLConnection 客户端。
- `server/src/main/java/com/pethospital/shared/S3StorageProperties.java`：显式内部 endpoint、公网 endpoint、region、bucket 与应用凭据配置。
- `server/src/main/java/com/pethospital/shared/ObjectStorageAdapter.java`：固定 bucket/path-style 的上传、读取和 60 秒 GET 预签名；使用静态凭据，不读取默认 AWS 凭据链；不暴露列桶、建桶和管理操作。
- `server/src/main/resources/application.yml`、`.env.example`：默认关闭 S3 Bean，启用时必须由环境注入凭据；内部和公网 endpoint 分开配置。
- `server/src/test/java/com/pethospital/shared/M0402IT.java`：连接真实 SeaweedFS，覆盖字节哈希、匿名拒绝、签名读取、过期拒绝和内部域名防泄漏。

适配器只接受无绝对路径、无反斜杠/父目录穿越/控制字符的对象键；非本机内部 endpoint 不允许直接复用为公网 endpoint，生成票据后再次核对 scheme/host/port。应用表面仅允许配置桶内对象 PUT/GET/预签名，不提供桶管理或对象枚举能力；部署凭据仍须按环境在 SeaweedFS/IAM 侧限制到 `pet-private`。

## 失败与修复记录

- AWS SDK 2.57.4 的 `S3Presigner.Builder`没有`clockOverride`：生产继续固定 60 秒，包内测试构造器只缩短真实过期用例的签名 TTL。
- 首次 M0402IT 因 Spring 无法在两个构造器间选择而 4 项上下文错误，业务断言尚未执行；显式标注生产构造器后完整复跑 4/4。
- Docker 只读入口路径和 Compose 服务名各误写一次，命令均未改变服务；使用核验后的 DockerDesktop 路径及 `qdrant` 服务名重跑成功。
