# M02-05 Mapper 和固定演示夹具验收

日期：2026-10-29。结果：通过。本任务建立MyBatis-Plus持久层基线、代表性真实表Mapper和显式固定demo夹具；未实现认证、业务Service或API，也未把33张表机械生成空Mapper。

## 实际改动

- `server/pom.xml`：加入MyBatis-Plus Boot3 starter3.5.18与同版本`mybatis-plus-jsqlparser`；没有混用普通MyBatis Spring Boot starter。
- `server/src/main/resources/application.yml`：全局启用下划线转驼峰与`ASSIGN_ID`；既有MySQL会话和Jackson UTC设置保持不变。
- `server/src/main/java/com/pethospital/persistence/MybatisPlusConfig.java`：注册乐观锁和MySQL分页插件，分页插件最后加入。
- `server/src/main/java/com/pethospital/persistence/JsonNodeTypeHandler.java`：统一JsonNode读写，序列化器固定UTC；SQL转换错误显式抛出。
- `server/src/main/java/com/pethospital/persistence/entity/AiSessionEntity.java`与`mapper/AiSessionMapper.java`：映射真实`ai_session`表，覆盖`@TableId(ASSIGN_ID)`、JSON、Instant和`@Version`。
- `server/src/main/java/com/pethospital/persistence/demo/`：固定保留ID、事务式反向删除/重建和独立CLI。创建5个虚构账号（两用户、两医生、一管理员）、3个角色与5条账号角色关联、2个医生档案、2只宠物、2条健康日志、2个时段、1个预约及状态日志、1个AI会话、1篇指南和1条健康标准。
- `tools/import-demo.ps1`：独立导入命令。要求`DB_URL`、`MYSQL_USER`、`MYSQL_PASSWORD`、`DEMO_PASSWORD`和精确确认串；CLI拒绝prod/production及非本机MySQL URL。密码不写入源码、参数或日志，只从进程环境读取并保存BCrypt哈希。
- `server/src/test/java/com/pethospital/M0205IT.java`：4组真实MySQL验收；普通应用启动时固定账号为0，证明夹具不自动创建。
- `README.md`、`tools/versions.lock.md`：记录demo命令、安全边界和实际解析的MP/MyBatis/JSqlParser版本。

## 真实验收断言

1. `ai_session`通过Mapper写入并读回结构化JsonNode，数组/字符串保持一致。
2. MySQL会话为UTC，`2035-04-05T06:07:08.123Z`经`DATETIME(3)`往返毫秒完全一致。
3. 主键`9,000,000,000,000,123,456`精确往返；空ID由MP生成正数雪花ID且大于JavaScript安全整数上限。
4. MySQL分页返回正确total/pages/records；`@Version`首次更新递增到1，陈旧版本更新行数为0且不能覆盖新值。
5. 固定夹具连续重建后各表数量不增加，固定ID和业务关联完整；M0205IT还使用Testcontainers本机URL执行CLI的Flyway+重建主体，每次由环境密码生成新BCrypt盐/hash，明文不落库。
6. 普通应用启动不创建任何固定账号，也不注册DemoFixtureService/Command Bean；缺少密码、production profile和远程数据库URL均被CLI配置校验拒绝。

## 限制

- 当前只提供`ai_session`代表性实体/Mapper来验收统一持久层基线；其余表在对应业务模块按实际用例增加实体和Mapper，避免提前堆积无行为代码。
- Demo CLI仅允许本机MySQL并使用固定负数保留ID，面向本地演示/测试；它不是生产初始化或通用数据迁移工具。
- 固定夹具不创建临床病历或AI最终答复，避免把虚构内容误认成正式医疗记录；真实业务闭环仍未实现。
- Flyway11.7.2仍提示官方测试范围到MySQL8.1；本任务和回归均已在MySQL8.4.13真实通过。
