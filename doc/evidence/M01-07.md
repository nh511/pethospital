# M01-07 持久任务和事务测试工具验收

日期：2026-10-28。结果：通过。范围仅为后续持久任务、事务和外部HTTP适配器提供测试工具，不代表正式业务表、预约事务、知识索引任务或真实外部模型已经实现。

## 实际改动

- `server/pom.xml`：沿用 `it` Failsafe profile，新增BOM管理的测试范围 MySQL Connector/J；Testcontainers版本由Spring Boot3.5.16 BOM固定为1.21.4。
- `server/src/test/java/com/pethospital/testing/MySqlTestContainer.java`：固定启动 `mysql:8.4.13` 隔离库；Docker不可达时明确失败，不回退H2、不跳过。
- `JdbcTransactions.java`、`FailureInjector.java`：统一JDBC事务提交/回滚及命名故障点注入。
- `ConcurrentTestBarrier.java`：带超时的并发就绪/释放屏障，避免用随机sleep制造竞态。
- `FixedHttpStub.java`、`HttpStubTest.java`：在loopback随机端口提供固定429、500、503响应；使用真实JDK HttpClient请求验证状态、正文、`Retry-After`及调用计数。
- `TestTags.java`：区分 `http-stub`、`mysql-it`、`real-service`；stub结果不能记作真实外部服务通过。
- `M0107IT.java`：测试专用InnoDB探针表，覆盖MySQL版本/隔离库、故障后整事务回滚、两个worker并发唯一领取、worker token与generation fencing。
- `README.md`、`tools/versions.lock.md`：补充命令、标签、依赖和测试辅助镜像版本记录。

## 实际执行与结果

首次离线运行 `test` 时，新增的 `com.mysql:mysql-connector-j:9.7.0` 尚未缓存在 `.tools/m2`，Maven明确以依赖不可解析退出；这次未计通过。获批联网后只下载该BOM管理的测试依赖，随后验证均可离线运行。

```powershell
& .\tools\run-maven.ps1 -JavaHome $env:JAVA_HOME -MavenArgs @('test')
```

结果：退出0，`BUILD SUCCESS`；Surefire共21项（既有20项 + HttpStubTest 1项），0失败、0错误、0跳过。

```powershell
& .\tools\run-maven.ps1 -JavaHome $env:JAVA_HOME -MavenArgs @('-o','-Dgroups=http-stub','test')
```

结果：退出0，只运行 `HttpStubTest` 1项，0失败、0错误、0跳过，证明stub标签可独立筛选。

```powershell
& .\tools\run-maven.ps1 -JavaHome $env:JAVA_HOME -MavenArgs @('-o','-Pit','-Dit.test=M0107IT','verify')
```

最终结果：退出0，`BUILD SUCCESS`。命令先运行Surefire 21项，再由Testcontainers1.21.4连接Docker Desktop Linux Engine29.7.2，启动隔离的 `mysql:8.4.13`；Failsafe运行M0107IT 4项，0失败、0错误、0跳过，耗时20.64秒。报告：

- `server/target/surefire-reports/TEST-com.pethospital.HttpStubTest.xml`
- `server/target/failsafe-reports/TEST-com.pethospital.M0107IT.xml`
- `server/target/failsafe-reports/failsafe-summary.xml`

最终执行 `docker ps -a --filter label=org.testcontainers=true` 退出0且无输出，确认MySQL与Ryuk临时容器均已清理。项目原有 `pet-hospital` 容器组及命名卷未被停止、删除或修改。

## 验收断言

1. `SELECT VERSION()` 实际返回8.4.13系列，`SELECT DATABASE()`为临时 `pet_hospital_it`，未连接项目MySQL，也未使用H2。
2. 第一次INSERT后注入异常，事务回滚后探针表计数为0。
3. 两个真实JDBC事务通过屏障同时执行条件UPDATE，领取结果恰为1和0，最终只有一个RUNNING任务。
4. 错误worker token或generation均无法完成任务，只有当前token+generation更新1行。
5. HTTP stub的429/500/503响应固定且可按 `http-stub` 标签单独运行；真实外部服务测试保留 `real-service` 标签，本任务未伪造真实DeepSeek或微信调用。

## 限制

- 探针表只存在于Testcontainers临时库，不是M02的33张正式业务表或Flyway迁移。
- M0107IT依赖可访问的Docker引擎；普通sandbox无法访问named pipe时需在授权环境运行，这是权限边界，不是Docker故障。
- 未验证DeepSeek、微信、Embedding或正式业务事务；这些仍按后续任务和真实凭据分别验收。
